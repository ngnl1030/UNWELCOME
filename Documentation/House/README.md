# 주택 블록아웃 사용 안내

실제 대상 씬은 `Assets/Scenes/GameScene.unity`입니다. 문서의 Game_Scene과 이름이 달라 기존 씬을 그대로 사용했습니다.

## 배치와 보존

- House_Root 위치 (0, 0, -14), 폭27m × 깊이21m, 층고3.2m.
- 지하 바닥 -3.2m, 1층 0m, 2층 3.2m. 현관은 월드 Z=-3.5 쪽입니다.
- 플레이어 프리팹, 스폰 시스템 코드, 네트워크 설정, 조작·카메라·함정 스크립트는 유지했습니다. 아이는 1층 거실/식당 안, 도둑은 현관에서 앞쪽으로12m 떨어진 외부에서 집을 바라보고 시작합니다.
- 기존 Playground는 원본 그대로 비활성화했습니다. House_Root/ExteriorGround의 분할 바닥이 주변을 채우고 지하실 위를 막지 않습니다.
- 되돌리기: House_Root 비활성화 + 기존 Playground 활성화. 원본 씬 백업은 Documentation/House/GameScene.before-house.unity.txt입니다.

## 평면 구성

현관을 바라보고 들어가면 중앙 홀, 좌우 생활 공간, 뒤쪽 중앙 계단이 나옵니다.

| 층 | 방 | 동선 |
|---|---|---|
| B1 | 대형 창고, 기계실, 비밀 보물방 | 중앙 복도와 각 방 출입구 연결 |
| 1F | 현관 홀, 거실, 식당, 서재, 주방 | 홀 양쪽 방 + 앞뒤 방 연결로 순환 가능 |
| 2F | 안방, 아이방, 손님방, 욕실, 놀이방 | 중앙 홀·계단참에서 연결, 욕실은 놀이방 쪽 출입구 |

중앙 계단 두 개 중 왼쪽은 지하로, 오른쪽은 2층으로 이어집니다. 계단 폭2.8m, 수평 길이7.5m, 경사 약23.1도입니다. 디딤판은 시각용이고 연속 경사 Collider로 걸어서 이동합니다. 기존 캐릭터의 계단 높이 설정을 바꾸지 않았습니다.

출입구 폭2.2m, 높이2.6m. 기본 복도 폭3.6m. 창문도 벽 조각 사이의 실제 개구부입니다. 유리나 문 개폐는 없습니다.

## 편집

1. GameScene을 열고 Play를 멈춥니다.
2. Tools > House Generator를 엽니다.
3. 폭·깊이·층고·벽 두께·복도 폭·계단 폭/길이·문 크기·앞쪽 방 비율을 조절합니다.
4. Generate / Regenerate House를 누르고 씬을 저장합니다.
5. 층별 체크박스로 표시/숨기기를 할 수 있습니다. 플레이 전 모든 층과 Roof, ExteriorGround를 다시 켜세요.

House_Root의 위치는 Transform으로 조절합니다. 방 이름은 각 층 Rooms 아래에 있습니다. 방 위치의 작은 Point Light는 내부 확인용 기본 조명이며 가구는 배치하지 않았습니다. Roof/Doors_Windows/Furniture_Placeholders는 별도 그룹입니다.

재생성 시 생성된 구조물 편집은 초기화됩니다. 치수에는 캐릭터가 통과할 수 있는 범위 검사가 있으며, 허용되지 않는 값은 콘솔에 설명을 표시하고 기존 구조물을 유지합니다. 층을 숨기면 해당 층의 충돌체도 꺼집니다.

## 실행

멀티플레이는 MainMenu에서 시작하세요. 호스트 → 슬롯 선택 → 컴퓨터 채우기 → 준비 → 시작으로 새 주택 맵에 진입합니다. GameScene만 직접 Play하면 기존 설계상 네트워크 캐릭터가 자동 생성되지 않습니다.

## 검증

- 큰 캐릭터 기준 캡슐 공간 검사 + 경로 탐색으로 모든 방과 홀 연결을 확인했습니다.
- 기존 두 캐릭터 CharacterController의 크기·경사/스텝 설정을 복제하여 현관에서 지하와 2층까지 실제 Move 충돌 계산으로 이동시켰습니다.
- 재생성 중복 생성 방지와 사용자 추가 오브젝트 보존을 확인했습니다.
- 정적 경로/충돌 결과: Validation.txt. 수동으로 모든 카메라 각도와 가구 배치까지 검증한 것은 아닙니다.

사용자가 생성 그룹 안에 추가한 오브젝트는 재생성 시 House_Root 바로 아래로 이동하여 월드 위치를 보존합니다. 직접 생성된 벽 자체에 붙인 컴포넌트는 재생성 때 초기화됩니다.

새 맵 Windows 빌드 성공(오류 0). 실제 Relay의 독립 실행 프로세스 2개로 사람 2명+컴퓨터 2명 캐릭터 생성, 입력·카메라 소유권, 컴퓨터 이동, 호스트/참가자의 함정 설치 동기화 및 종료 처리를 통과했습니다. 런타임 오류 0. 결과: MultiplayerTestResult.json. 이 검증은 최초 주택 제작 당시 결과입니다. 최신 확대/스폰 변경 결과는 아래를 확인하세요.

미리보기: Exterior.png, Basement_B1.png, FirstFloor_1F.png, SecondFloor_2F.png. 위에서 찍은 평면 이미지에서는 문 위 인방 때문에 출입구가 가려 보일 수 있지만, 바닥 높이에서 실제로 열린 출입구입니다.


## 1.5배 확대 및 팀별 스폰

가로·세로 각각1.5배(바닥 면적2.25배)로 확대했습니다. 층고는3.2m 유지. Front Room Fraction .45, 복도3.6m, 계단 폭2.8m/길이7.5m, 출입구 폭2.2m입니다. House Generator에서 이 값들이 저장되어 재생성해도 유지됩니다.

- KidSpawn01: (-6, 0.15, -8), 1층 거실
- KidSpawn02: (6, 0.15, -8), 1층 식당
- ThiefSpawn01: (-6, 0.15, 8.5), 외부
- ThiefSpawn02: (6, 0.15, 8.5), 외부

도둑 두 명은 집 방향(Y회전180도)을 바라봅니다. 스폰 좌표는 PlayerSpawnManager 아래의 Transform만 조정했습니다. House Generator는 스폰을 덮어쓰지 않습니다. 각 지점의 2m 캡슐 여유 공간과 바닥, 모든 방 접근 및 두 캐릭터의 층간 이동 검사를 통과했습니다. 확대 전 씬 백업: GameScene.before-enlarge.unity.txt.

최신 확대 맵도 실제 Relay 독립 프로세스2개(사람2+컴퓨터2)의 캐릭터 생성·카메라/입력 분리·이동 및 양쪽 함정 설치 동기화·종료 테스트를 통과했습니다. 빌드 오류0, 테스트 런타임 오류0. 결과: EnlargedMultiplayerTestResult.json.
